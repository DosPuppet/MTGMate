# Le moteur : carte des fichiers et recettes d'extension

Moteur pur et déterministe (`packages/engine/src`). L'état est sérialisable ; les effets sont des données (DSL), jamais des fonctions.

## Fichiers

| Fichier | Rôle |
|---|---|
| `types.ts` | Types de base (`Color`, `ManaCost`, `CardType`, `Keyword`, `RESTRICTIONS`) ; réexporte `model/*`. On importe toujours depuis `types.ts`. |
| `model/cards.ts` | `CardDef`, capacités (activées, déclenchées, statiques, de mana, de joueur, remplacements, doublements), coûts, `LayerMods`, `TokenSpec`, `MoveSpec`. |
| `model/rules.ts` | `ObjectFilter`, `TargetSpec`/`TargetFilter`, `TriggerSpec` (union `on`), `Condition`, `Ref`, `Amount`. |
| `model/effects.ts` | `Effect` (union `op`). |
| `model/state.ts` | `GameState`, `GameObject`, `PlayerState`, `StackItem`, combat, déclencheurs en attente, `LkiSnapshot`. |
| `model/decisions.ts` | Décisions, choix, options d'action, `GameEvent`. |
| `dsl.ts` | Constructeurs pour les scripts de cartes : `fx.*`, `when.*`, `cond.*`, `amount.*`, `ref.*`, `target.*`, `activated`, `triggered`, `staticAbility`, `playerStatic`, `manaAbility`, `chapter`, `spree`, `tiered`… Plus `CardScript` (champs du script d'une carte). |
| `effects.ts` | `runEffect` : aiguillage vers la table `op → traitement` ; `evalAmount` (`switch (a.kind)`) ; `resolveRef` ; `evalCondition` ; aides partagées (`store`, `damageSource`, `moveWithSpec`, `grantPlay`, `addEffect`…). |
| `ops/*.ts` | Les traitements des effets, par domaine : `damage`, `players`, `counters`, `zones`, `spells` (pile, permissions de lancer), `permanents` (modifications, contrôle, copies, jetons), `mana`, `flow` (si, peut, réflexif, retardé). Chaque fichier exporte `HANDLERS: OpHandlers`. |
| `triggers.ts` | Détection des déclencheurs (`switch (t.on)` sur les `RulesEvent`), doublements de déclenchements, `checkCondition` (`switch (c.kind)`), capacités retardées. |
| `stack.ts` | Lancer (`castTerms`, `castableFaces`, `castSpell`), coûts, activer (`activateAbility`, `canPayNonManaCost`), résoudre, contrecarrer, jouer un terrain. |
| `control.ts` | Couche 2 : contrôleur de base (`baseController`), effets de contrôle horodatés (`addControlEffect`), Auras qui donnent le contrôle ; `syncControl` recalcule le contrôleur de chaque permanent (actions basées sur l'état, nettoyage, 800.4a). |
| `stackChoices.ts` | Copies de sorts et de capacités (`copyStackItem` : une copie de sort est un objet sur la pile) ; choix d'un élément déjà sur la pile, posés avant la priorité (`announceNext`) : nouvelles cibles d'une copie (707.10c), répartition (601.2d, gardée dans `StackItem.division`). |
| `legal.ts` | `legalActions` : options proposées aux joueurs et à l'IA (doit refléter `stack.ts`). |
| `layers.ts` | Couches 613 (`chars`, cache par `s.version` → `bump(s)`), dépendances 613.8 par point fixe (`collectStatics`, `applyLayers`), `copiedDefId` (face active, copie) et `copiableExceptions` (707.9b), `snapshot`/`view` (vue d'un objet pour les filtres). |
| `targets.ts` | `matchesView` (filtres d'objets), légalité et validation des cibles. |
| `actions.ts` | Blessures (`dealDamage` : préventions, doublements, redirection), pioche, PV, jetons, sacrifice. |
| `state.ts` | Objets, zones (`moveObject` et remplacements de destination), marqueurs, `RulesEvent`, `setController`. |
| `modifiers.ts` | Remplacements qui modifient un nombre (« autant plus N », « le double », « au moins N ») : ordre choisi pour le joueur affecté (616.1, `chooseReplacementOrder`). |
| `replacement.ts` | Remplacements d'arrivée (`applyEntersReplacements`) et de destination (`replaceDestination`). |
| `turn.ts` | Étapes, actions basées sur l'état (Sagas, Auras…), combat, élimination, tours et étapes supplémentaires. |
| `mana.ts` | Capacités de mana, solveur de paiement, mana restreint. |
| `statics.ts` | Index des capacités par contrôleur (`controlledAbilitiesWithSource`, `playerStatic`) ; remplacements d'événements chiffrés en vigueur (`eventReplacements`, `quantityMods`, `recipientMatches`). |
| `view.ts` | Projection de l'état pour un joueur (information cachée). |
| `scenario.ts` | `createScenario` : partie mise en scène (bibliothèques dans l'ordre, mains, permanents, tour de départ, mulligan facultatif) pour le tutoriel ; l'état vide vient de `blankState` (`game.ts`). |
| `host.ts` | `GameHost` : IA, automatisme et humains ; l'option `gate` met l'IA en pause (explications du tutoriel). |
| `game.ts` | API publique : `createGame`, `submit` (copie de travail, l'état reçu n'est jamais modifié), `applyMutable` ; détection des boucles d'actions obligatoires (104.4b). |
| `choices.ts` | Choix génériques : validation des réponses (`validateChoice`), construction des demandes, `cardRef` (repère d'une carte dans un texte, localisé par le client). |
| `autopilot.ts` | Automatisme « façon Arena » : réponses aux décisions triviales (arrêts, contrôle total, passes douce et dure) ; le moteur reste strict. |
| `record.ts` | Enregistrement d'une partie (graine, decks, décisions, points de contrôle) et rejeu vérifié (`replayChecked`) ; `RULES_VERSION` et son historique. |
| `fingerprint.ts` | `outcomeHash` : empreinte canonique d'un état, sans identifiants internes (points de contrôle, boucles obligatoires). |
| `decisionShape.ts` | Forme d'une décision reçue (types des champs, objets inconnus, doublons), vérifiée par `apply` (`game.ts`) avant les règles. |
| `errors.ts` | `RulesError` et `rethrowAsRules`. |
| `events.ts` | Collecteur des événements d'affichage (`collectEvents`, `emit`), sans dépendance : tout fichier peut émettre. |
| `limits.ts` | Plafonds de sécurité (voir plus bas) et `capReached`. |
| `turnlog.ts` | Journal des événements du tour (`s.turnLog` : déplacements publics, sorts lancés, attaques, sacrifices, marqueurs, activations, blessures, vie gagnée et perdue, pioches, défausses, regards, crimes, retournements) et requêtes (`countTurnEvents` : nombre, somme `sum`, valeurs différentes `distinct`, dont `distinct: "object"` : créatures différentes qui ont attaqué). « Un adversaire » (`who: "opponent"`) : un adversaire encore en partie. |

## Recettes

- **Nouvel effet :** ajouter la variante `{ op: "…" }` à `Effect` (`model/effects.ts`), son traitement `op(s, r, e, ctx, key) { … }` dans le `HANDLERS` du bon fichier `ops/<domaine>.ts` (`e` y est typé selon `op` ; `r` et `key` servent aux choix et aux variables mémorisées), puis son constructeur `fx.…` (`dsl.ts`). Si l'effet change des caractéristiques, appeler `bump(s)`.
- **Nouveau déclencheur :** une variante de `TriggerSpec` (`model/rules.ts`), un `case` dans `triggers.ts` (renvoyer `{ objectId, player, amount }` pour `ref.eventObject`, `ref.eventPlayer` et `amount.eventAmount`), puis `when.…`. Si l'événement n'existe pas, ajouter un `RulesEvent` (`state.ts`) et l'émettre avec `rulesEvent(s, …)`.
- **« … ce tour-ci » (compter ce qui s'est passé pendant le tour) :** pas de nouveau compteur dans `TurnStats` (réservé aux compteurs propres à une règle : ordre des sorts, première pièce…), pas de nouvelle condition `…ThisTurn` ; utiliser le journal du tour, `amount.turnEvents({ event, who, types, from, to, … })` (`turnlog.ts`), avec `cond.amountAtLeast`. S'il manque un événement ou un champ, l'ajouter à `TurnLogEntry` (`model/state.ts`) et à son enregistrement.
- **Compter, additionner, comparer des objets :** pas de nouvelle sorte de montant ; `aggregate` (`fn` : somme, plus grande valeur, valeurs différentes ; `property` : force, endurance, valeur de mana, couleur, type, sous-type, nom, marqueurs… ; objets du filtre, d'une zone ou désignés par `of`) avec les aides `amount.totalPower`, `amount.maxManaValue`, `amount.colorsAmong`…, et une `property` de plus si besoin (`propertyValues`, `effects.ts`). Ce qui a été dépensé pour lancer un sort : `spent` (X, mana, couleurs, Cavernes). « Chaque joueur / adversaire qui … » : la référence `playersWhere` (condition évaluée du point de vue de chaque joueur), avec `refCount`.
- **« S'il a été lancé … » :** `cond.cast({ from, via })` (zone de lancement, coût alternatif : Web-slinging, chaos, faufilement, évocation, distorsion, imminence) ; ce qui a été dépensé : `amount` `spent`. Tout se lit dans `CastInfo` (`castInfoOf`, `state.ts` : l'élément de pile `StackItem.cast`, puis le permanent `GameObject.cast`) ; une nouvelle information de lancement y va, pas dans un champ de `StackItem` ou de `GameObject`.
- **Nouvelle condition ou nouveau montant :** `Condition` + `checkCondition` + `cond.…` ; `Amount` + `evalAmount` + `amount.…`. Deux évaluateurs de conditions, aux rôles distincts : `evalCondition` (`effects.ts`, pendant une résolution : cibles, X, valeurs mémorisées) traite les sortes qui en dépendent et délègue les autres à `checkCondition` (`triggers.ts`, hors résolution : statiques, déclencheurs, coûts) ; quelques sortes existent dans les deux avec une sémantique propre à chaque moment (`refMatches` hors résolution lit l'objet de l'événement). Un contexte hors résolution se construit toujours avec `staticContext` (`effects.ts`). Un montant utilisé dans une F/E définie par une capacité ou un `perAmount` doit être dans `CDA_AMOUNT_KINDS` (`layers.ts`, `cdaValue` ; un agrégat par sa clé `cdaKey`), ce que vérifie `cards/test/cda.test.ts`.
- **Filtre d'objet :** un champ de `ObjectFilter`, calculé dans `view()` (`layers.ts`) si besoin, et testé dans `matchesView` (`targets.ts`).
- **Statique de joueur :** un champ de `PlayerStaticAbilityDef` (seulement si aucune forme générique ne convient : règle en fin de CLAUDE.md), lu avec `playerStatic`, `playerStaticTotal` ou `playerStatics(s, p, "clé")` (`statics.ts`), qui vérifient la condition et comptent les effets sur les joueurs. Jamais en filtrant `controlledAbilitiesWithSource` sur `kind === "playerStatic"`.
- **Restriction, mot-clé technique :** ajouter à `Keyword` et `RESTRICTIONS` (`types.ts`), avec son libellé dans `client/src/i18n.ts` (sinon `tsc` échoue).
- **Champ de script de carte :** dans `CardScript` (`dsl.ts`), `CardDef` (`types.ts`) et la recopie dans `toCardDef` (`cards/src/scryfall.ts`).
- **Capacité de mana à coût (« {1}, {T} : ajoutez un mana de n'importe quelle couleur ») :** une capacité `activated` ordinaire suffit ; `isManaAbility` (605.1a) la résout sans la pile.
- **Remplacement qui modifie un nombre** (blessures, marqueurs, PV, pioche) : l'ajouter comme `AmountMod` (`add`, `times`, `atLeast`) dans la liste de l'événement (`dealDamage`, `changeCounters`, `gainLife`, `drawCards`), jamais en modifiant la quantité directement ; l'ordre est choisi par `chooseReplacementOrder`. Une pioche passe par `drawCards` (sauf la main de départ).
- **Blessures et perte de PV : remplacements et préventions** (R1, familles E et F) : une capacité `eventReplacement({ event: "damage" | "lifeLoss", source, to, toFilter, combat, modify: { add, times, atLeastSourcePower, prevent }, onPrevent, condition })`, ou un effet `fx.thisTurn({ replacement })` ; bouclier « la prochaine fois que » : `fx.shield(remplacement, choixDeLaSource)`. Collecteur : `eventReplacements` (`statics.ts`) ; application : `dealDamage` et `loseLife` (`actions.ts`), préventions d'un autre joueur que le blessé avant les modifications, les siennes après (616.1).
- **« Si [un objet] devait être mis dans un cimetière, exilez-le à la place » :** une capacité `graveyardReplacement({ filter, fromBattlefield, graveyardOf, notControlledByYou, link, gainLife, condition })`, et non un drapeau de `playerStatic`. L'ordre de 616.1 est appliqué par `replaceGraveyard` (`replacement.ts`), appelé par `moveObject`.
- **« Vous pouvez lancer [cette carte] » pendant une résolution (608.2g) :** `fx.castNow(ref, { free, many, exileAfter, anyMana, storeCast, storeRest })`, et non `fx.grantPlay` (qui laisse la carte lançable plus tard dans le tour). Depuis un traitement d'effet, la boucle `castNowLoop` (`ops/spells.ts`) renvoie `{ castNow: … }`, qui suspend la résolution sur une priorité restreinte (`PendingDecision.castNow`).
- **Effet sur un joueur jusqu'à la fin du tour** (« les blessures ne peuvent pas être prévenues ce tour-ci ») : `fx.thisTurn({ clé: valeur })`, avec une clé de `PlayerStaticAbilityDef` déjà lue par le moteur ; pas de nouvel effet.
- **Coût payé avec des objets** (flétrir, preuves, exil du cimetière, sacrifier X, convocation…) : un emplacement `CostSlot` (`model/decisions.ts`) décrit dans `activationPicks` (capacités) ou `spellPicks` (sorts), dans `stack.ts`, avec ses options et sa suggestion (le choix du moteur) ; au paiement, `pickNow` / `spellPickNow` appliquent le choix du joueur (`CastChoices.picks`, vérifié par `resolvePick`) ou la suggestion. `legalActions` publie les emplacements où le joueur a un choix (`ActionOption.picks`), et l'interface les demande (`CostPickPicker`). Jamais un choix d'objet écrit en dur dans `castSpell` ou `activateAbility`.
- **Coût alternatif qui change le texte** (surcharge, fendre) : un second mode lancé pour son propre coût, `ModeDef.cost` (aide `altCostMode`) ; jamais gratuit ni avec un autre coût alternatif (118.9a). Escalade : `escalate(coût, …modes)`, toutes les combinaisons avec leur surcoût, comme `spree`. Un coût alternatif que d'autres règles lisent porte son nom dans `altCost.via` (ruée : célérité et retour en main, lus par `cond.castVia("dash")`) ; ruée et spectacle sont déduits du texte (`scryfall.ts`).
- **Mots-clés de permanent lus dans le texte** (`scryfall.ts`, à ne pas réécrire dans un script) : exaltation, affinité pour les artefacts (`costReduction`), modulaire N, greffe N, extorsion, déluge (`castSelf`, dont `amount.eventAmount` est le nombre de sorts lancés avant celui-ci ce tour-ci par tous les joueurs) ; défense totale est un mot-clé (`shroud`, refusé comme cible dans `isLegalTarget`). Champion : l'aide `champion(filtre, libellé, suite)` de `spg/cards.ts`.
- **Capacité de mana avec contrepartie** (Ancient Tomb : blessures à vous ; Grove of the Burnwillows : PV aux adversaires) : `manaAbility(…, { drawback })`, appliquée en résolvant la capacité (605.3b) ; la capacité reste utilisable par le paiement automatique. **« Engagez un [permanent] dégagé que vous contrôlez » en coût d'une capacité de mana :** `manaAbility(…, { tapAnother })` (`true`, `"creature"`, `"artifact"` ou un `ObjectFilter` : créature légendaire de Relic of Legends ; sans {T} : `noTap`), le permanent étant choisi par le moteur (`otherToTap`, `mana.ts`) et partagé entre les sources par le solveur.
- **Régénération** (701.19) : `fx.regenerate(ref)` donne un bouclier (`GameObject.regenShields`) que `destroy` consomme (engagé, retiré du combat, blessures retirées) ; les boucliers disparaissent au nettoyage. **Infection** : mot-clé `infect` (`dealDamage` : −1/−1 aux créatures, poison aux joueurs). **Mana calculé :** `manaAbility(…, { colorsOf })` (couleurs de vos permanents), `{ likeLands }` (types de vos terrains), `{ linkedColors }`. **Main de départ :** `leyline` accepte `{ notStartingPlayer, counter, exileFromHand }`.
- **Statique de joueur qui touche d'autres joueurs** (« les joueurs ne peuvent pas gagner de PV ») : `playerStatic({ …, affects: "each" | "opponents" })` ; la statique est rangée pour chaque joueur concerné. **Traversée de terrain :** `block.landwalk(type, libellé)`. **Suspension** (702.62) : lue dans le texte, une action spéciale depuis la main (`suspendCard`).
- **Mana phyrexian** (107.4f) : `ManaCost.phyrexian` (`{B/P}`), payé dans `canPay` et `payMana` avec du mana si possible, sinon 2 PV par symbole (choix automatique) ; la statique de joueur `phyrexianMana` rend phyrexians les symboles d'une couleur de vos coûts (K'rrik).
- **Règles de défaite et de victoire :** statiques de joueur `cantLose` (« vous ne pouvez pas perdre et vos adversaires ne peuvent pas gagner »), `noLoseForLife`, `winOnEmptyDraw` (la pioche impossible devient une victoire : `drewFromEmptyLibrary = "win"`, constatée par `checkGameOver`), `damageLifeFloor` (blessures plafonnées au-dessus d'un plancher, dans `loseLife(…, damage)`), `infectDamageAtZeroLife`. **Mana multiplié :** `eventReplacement({ event: "mana", modify: { times } })`, ordonné avec les `add` par `manaAmount` (`mana.ts`), que le solveur lit aussi. **Dé :** `fx.rollDie(faces, store)` (op `coinFlip` avec `sides`, résultat dans la variable). **Mue** (702.37) : lue dans le texte (`parseDisguise`, `CardDef.morph`), comme le déguisement sans la garde.
- **Filtre relatif à un objet désigné** (« de force supérieure à celle de la créature ciblée », « qui partage un type de créature avec elle ») : `powerAboveOf`, `sharesCreatureTypeWith` (une `Ref`), remplacés par une borne ordinaire dans `withX` (`effects.ts`), donc seulement dans les références de zone, `moveAll` et la recherche. **Combat :** `ref.combatPartners(r)` (bloqueurs de r et créatures qu'il bloque) ; statiques de joueur `maxBlockingCreatures` et `maxOneAttacker`. **« Un sort ou une capacité … détruit »** : `destroy(s, id, noRegenerate, by)` émet l'événement `destroyed` (déclencheur `when.destroyedByOpponent`) ; la destruction par les actions basées sur l'état n'en émet pas.
- **Défausse :** toute carte défaussée passe par `moveDiscarded` (`effects.ts`, `byEffect` pour une défausse due à un effet), puis `announceDiscard` ; jamais `moveObject(…, "graveyard")` directement (la folie, 702.35, l'envoie en exil). **Mots-clés de lancer lus dans le texte :** folie (`madness`), émerger (`altCost.pay.sacrificeReduce`), réplique (kicker de sorte `replicate` : X fois le coût, X du sort), retrace (`castFromGraveyard.discardFilter`). **Copie à l'arrivée :** exceptions dans `entersAsCopyMods` (`LayerMods` copiables).
- **Phasing** (702.26) : `phaseOut(s, id)` (`actions.ts`) retire le permanent et ce qui lui est attaché du champ de bataille sans changement de zone (zone `phasedOut`, liste `PlayerState.phasedOut`) ; `phaseIn` les rend au début de l'étape de dégagement de leur contrôleur. **Un autre joueur choisit ou paie :** `chooseOption.who` (`fx.yourChoice(…, who)`), `payX.who` (`fx.payLifeX(…, who)`). **« Votre prochain sort ce tour-ci »** : `NextSpell.trigger` (`fx.whenNextSpellThisTurn`), le sort étant `ref.target("s")`.
- **Coûts lus dans le texte :** Harmonie (`CardDef.harmonize`, coût dans `flashback`, créature engagée par `CastChoices.tap`) et Marchandage (kicker {0} avec `kickerCost.sacrifice`, permanent choisi par `CastChoices.sacrifice`) sont déduits dans `scryfall.ts` ; une carte qui les a n'a rien à écrire.
- **Contempler, maîtrise de la terre :** `cond.behold(filtre)` ; `fx.earthbend(ref, n)`. En coût additionnel : `additionalCost.behold` (`required` : obligatoire ; `exiled` : une carte exilée au lieu d'une carte de la main), l'objet choisi est lu par `ref.cost("beheld")` (Monstrous Emergence, Close Encounter).
- **Mana restreint à une sorte d'action :** `ManaRestriction.ability` (`AbilityKind` : Équiper, déverrouiller une porte, retourner face visible, exhaust…), reconnue par `isAbilityKind` (`stack.ts`) et portée par `abilityPurpose` ; les modificateurs de coût des capacités (`AbilityCostMod.ability`) utilisent les mêmes sortes.
- **« Vous / un adversaire subissez des blessures » de toute source :** `when.playerDealtDamage("you" | "opponent", combat?)` (`isDealtDamage` avec un joueur) ; « par une source que vous contrôlez » reste `when.dealsDamage(…, { anySourceYouControl })`.
- **« Une ou plusieurs … » (déclenchement `batched`) :** les objets des autres événements du lot rejoignent le déclenchement en attente (`TriggerEventData.others`) ; `ref.eventObjects` les désigne tous (« ces créatures », `fx.chooseAmong` pour « l'une d'elles », `amount.totalPowerOf` : un objet parti du champ de bataille est lu dans ses dernières informations). `when.zoneChange` lit le contrôleur (`filter.controller`) et les types d'un objet qui quitte le champ de bataille au moment de partir, le propriétaire et la carte ailleurs. **« … pour la première fois chaque tour, si … » :** `oncePerTurn: "firstEvent"` (noté au premier événement, avant la condition, 603.4).
- **Capacité retardée liée à un objet** (603.7c : « quand cette créature meurt ce tour-ci », « quand vous perdez le contrôle de cet Équipement ce tour-ci ») : `fx.whenThisTurn(déclencheur, objets, effets, { targets, bind, label })` ; les objets sont figés à la création (`DelayedTrigger.watch`), l'objet de l'événement doit en être un (`ref.eventObject`), et la capacité prend fin avec le tour (`at: "thisTurn"`). Jamais une capacité accordée à l'objet ni un emblème du tour.
- **Tarkir: Dragonstorm :** endurance `fx.endure(ref, n)` ; rafale `when.castNthSpell(2)` ; mode choisi en arrivant (Sièges) `chooseOnEnter: "mode"`, `enterModes` et `cond.chosenMode` ; suspension `fx.suspend(ref, n)` ; cave accordée `playerStatic({ delveSpells })` ; décomposition (mot-clé et marqueur `decayed`).
- **Propriétaire, contrôleur, noms différents, destinataire des blessures :** filtre `owner: "you" | "opponent"` (toute zone ; « que vous possédez mais ne contrôlez pas » : avec `controller: "opponent"`) ; `ref.ownerOf(r)` ; `ref.controllerOf(r)` et le `controller` de `ref.filtered` lisent le dernier contrôleur connu d'un objet parti du champ de bataille ce tour-ci (608.2h, `lastController`), sinon le propriétaire hors du champ de bataille ; « de noms différents » : `differentNames` (cibles, `pickFromZone`, sacrifice en coût) ; déclencheurs `dealsDamage` / `dealsCombatDamage` : `to` (un `TargetFilter` : `TO_PLAYER`, `TO_OPPONENT`, `TO_PLAYER_OR_PLANESWALKER`, `TO_CREATURE`). « Son propriétaire met … au-dessus ou au-dessous » (deuxième depuis le dessus : `fromTop`) : `fx.topOrBottom`, demandé au propriétaire.
- **« … que ce joueur contrôle », « du cimetière de ce joueur » :** `target.of(joueur, spec)` (`TargetSpec.of`, une `Ref`) : le joueur de l'événement (`ref.eventPlayer` : joueur blessé, celui qui détruit), le joueur défenseur (`ref.defendingPlayer`), évalués au ciblage par `concreteSpec` (→ `ofPlayers`, lu par `isLegalTarget`) et de nouveau à la résolution (`stackItemSpecs`) ; ou le joueur d'un autre mot « cible » (`ref.target("p")` : Rite of Renewal), vérifié par `validateTargets` et publié pour l'interface et l'IA (`TargetOption.ofTarget`). Jamais `controller: "opponent"` à la place (faux à plusieurs).
- **Nouvelles cibles d'un sort déjà lancé :** `fx.changeTarget(r)` ; à cible unique, une autre cible au choix ; à plusieurs cibles (« vous pouvez choisir de nouvelles cibles » : Commandeer, Speedball), une question par mot « cible », celles d'origine proposées (`retargetRequest` et `applyRetarget`, `stackChoices.ts`, comme pour une copie).
- **Capacité accordée qui désigne le permanent qui l'accorde** (« la créature équipée a "…, engagez Fishing Pole : …" ») : la capacité est accordée par une statique (`addAbilities`) ; les couches retiennent l'objet qui l'accorde (`Characteristics.grantors`), l'activation le fige (`InlineAbility.bound`), l'effet le lit par `ref.grantor` et le coût par `CostDef.grantor` (`"tap"`, `"exile"`, `"sacrifice"`). Jamais la capacité portée par l'Équipement lui-même.
- **Phases et étapes ajoutées (500.8 à 500.10) :** `fx.extraCombat` (« après cette phase »), `fx.extraCombatsAfterMain(n)` (« après cette phase principale », sans phase principale entre eux : Full Throttle), `fx.extraCombatAfterMain` (un combat suivi d'une phase principale), `fx.extraUpkeeps(n, afterStep)` (une phase de début réduite à son entretien, ou une étape après celle-ci), `fx.extraEndStep`. Elles vont dans les files `turn.addedPhases` et `turn.addedSteps` (`addedNext`, `turn.ts`), la plus récente d'abord ; le tour reprend ensuite à `turn.resumeAt`. Une phase principale ajoutée est une `main2` ; son rang est `turn.mainPhase` (505.1a), lu par le déclencheur `step: "main"` avec `nth` (`when.secondMain`, `when.eachMain`).
- **Sorts sans payer leur coût de mana :** `castPermission({ freeFrom: "hand" | "any", freeFilter, freeOncePerTurn })` (la permission « une fois par tour » n'est consommée que si elle sert) et `fx.nextCreatureSpell({ free: true }, filtre)` (le prochain sort la consomme, payé ou non) : `freeCastTerms` (`stack.ts`), de toute zone, jamais avec un autre coût alternatif (flashback, chaos, présage, coût de remplacement). **Marqueurs retirés parmi vos créatures** pour lancer un sort (Quilled Greatwurm, Dawnhand Dissident) : emplacement `counterFrom` de `spellPicks` (`countersAmongPick`, un objet par marqueur, `repeat`).
- **Désignation de joueur pour le reste de la partie** (ascension, 702.131) : le mot-clé `ascend` (lu dans le texte) ; le contrôleur d'un permanent qui l'a et de dix permanents ou plus reçoit `PlayerState.citysBlessing`, posé avec les actions basées sur l'état (`stateBasedActionsOnce`, comme la vitesse et le récit durable), lu par `cond.citysBlessing`. L'ascension d'un éphémère ou d'un rituel (à la résolution) n'est pas faite tant qu'aucune carte ne l'exige. **« Les autres [créatures] arrivent avec … tant que … »** : `entersWith({ affects, condition })`, la condition vue du contrôleur de la source (Vampire Socialite).
- **Entretien cumulatif, rebond, taxes répétées (PLAN-E, E12) :** l'entretien cumulatif (702.24, « Cumulative upkeep {1} » ou « —Pay N life ») est lu dans le texte (`scryfall.ts`) et devient `cumulativeUpkeepAbility` (`dsl.ts`) : marqueur d'âge, puis `unlessPay` avec `times` (le coût payé une fois par marqueur, `timesCost`) ; le rebond imprimé est un mot-clé (`rebound`) lu dans le texte, comme le rebond accordé (`StackItem.rebound`). « Sauf la première carte qu'il pioche lors de chacune de ses étapes de pioche » : `when.drawExceptTurnDraw` (événement `draw` avec `turnDraw`). « … dans le cimetière d'un adversaire » : `when.zoneChange(…, { whose: "opponent" })`.
- **Nouveau champ de `GameState` :** l'initialiser dans `game.ts` et, si besoin, dans `engine/test/helpers.ts`. Les champs de tour se remettent à zéro au changement de tour (`turn.ts`).
- **Commander (903, PLAN-E) :** la variante `GameOptions.variant: "commander"` (40 PV par défaut, `defaultStartingLife`) et `PlayerSetup.commanders` (indices dans le deck) ; l'état `GameState.commander` (absent hors Commander) range chaque commandant par identité physique (`uid`, 903.3) avec sa taxe (`casts`) et ses blessures de combat par joueur (`damage`) ; `commanderOf(s, o)` (`state.ts`) dit si un objet est un commandant (jamais un jeton ni une copie). La zone de commandement contient des emblèmes (jetons) et des commandants : toute lecture des capacités qui y fonctionnent passe par `commandZoneAbilities` (`state.ts` : toutes celles d'un emblème, aucune d'une carte, 113.6), jamais par les capacités de la définition. Lancer depuis la zone : branche `source: "command"` de `baseCastTerms` (taxe dans `CastTerms.extraCost`, payée même gratuit), parcourue par `legalActions` et montrée par `playableElsewhere`. Retour : action basée sur l'état 903.9a (`commanderReturnOffer`, question oui/non `commanderZone`, une fois par objet) et remplacement 903.9b dans `moveObject` (vers la bibliothèque seulement, choix automatique). Blessures : `dealDamage` (combat) et `checkGameOver` (21, raison `commander`). Vue : `PlayerView.commanders` et `commanderDamage`. Tests : `engine/test/commander.test.ts` ; scénarios : `Side.command` des aides de test.

## Plafonds de sécurité

Des gardes empêchent une partie de boucler ou d'exploser ; elles déclarent la partie nulle ou coupent un montant. Toutes les constantes sont dans `limits.ts` ; une coupure émet l'événement `capReached` (journal de la partie) et le fuzz compte les coupures (« plafonds atteints »).

| Plafond | Où | Valeur | Effet |
|---|---|---|---|
| Étapes du déroulement | `turn.ts` | 100 000 | partie nulle |
| Passes d'actions basées sur l'état | `turn.ts` | 100 | partie nulle |
| Boucle d'actions obligatoires (104.4b) | `game.ts` | même empreinte 3 fois | partie nulle |
| Décisions automatiques par tour | `host.ts` | 10 000 | partie nulle |
| Jetons créés | `actions.ts` | 100 par événement, aucun au-delà de 400 objets | coupure |
| Montant remplacé | `modifiers.ts` | 1 000 000 | coupure |
| Ordre des remplacements chiffrés | `modifiers.ts` | 5 remplacements | ordre du code au-delà |
| Passes de couches (613.8) | `layers.ts` | 3 | arrêt du point fixe |

Tout plafond nouveau va dans `limits.ts`, dans ce tableau et dans `docs/approximations.md`.

## Règles de conception

- **Erreurs :**
  - une décision illégale ou mal formée lève une `RulesError` (l'IA, le serveur et le fuzz en dépendent) ;
  - toute autre `Error` est un bug du moteur ;
  - on ne convertit jamais une erreur quelconque en `RulesError`. Autour d'une étape qui peut être illégale (paiement, cibles), on passe par `rethrowAsRules(e, message)`, qui laisse remonter les autres erreurs ;
  - l'IA n'avale que les `RulesError` dans ses simulations ;
  - le fuzz « chaos » (`npm run fuzz -- --ai chaos`) soumet des variantes corrompues de chaque décision : elles doivent être refusées par une `RulesError`, sans modifier l'état reçu.
- **Invariants du fuzz** (`checkInvariants`, `ai/src/selfplay.ts`) :
  - zones, conservation des cartes, cache des couches ;
  - nombres finis ;
  - références (attachements, combattants) ;
  - aucune décision demandée à un joueur éliminé ;
  - état en JSON pur.
  
  Un nouveau champ d'état doit les respecter.
- Tout ce dont une statique ou une F/E variable dépend fait avancer la version d'état (`bump`). Le fuzz détecte les oublis (« cache des caractéristiques périmé »).
- **Invalidation ciblée** (`bumpFor`, `layers.ts`) : engager, dégager et payer du mana n'invalident le cache que si une statique, un effet ou une F/E définie par une capacité en vigueur lit l'état engagé (clé `tapped` d'un filtre) ou la réserve (`manaPoolAtLeast`). Une nouvelle forme qui lit l'un d'eux autrement doit être ajoutée à `scanDeps`. Les index qui suivent la version (`statics.ts` : statiques de joueur par clé, remplacements par événement ; `triggers.ts` : sources des déclencheurs, dont la clé porte aussi la composition des zones et les permanents engagés) se recalculent avec elle.
- Pas de nouveau drapeau, mot-clé, opération, propriété ou champ propre à une carte sans justification : règle en fin de CLAUDE.md, vérifiée par `cards/test/debt.test.ts` (référence `cards/data/debt-baseline.json`). Le test suit aussi la taille de chaque surface du modèle (`ceilings` : champs de `CardDef`, `GameObject`, `ObjectFilter`…, variantes d'`Effect`, `Amount`, `Condition`…), les champs « ce tour-ci » de `GameObject`, les noms de cartes écrits dans le code du moteur et le plus grand cycle d'imports (`importCycleMax`) : aucun ne peut grandir sans que la référence soit modifiée dans le lot.
- Préférer un mécanisme générique et nommé à un drapeau « pour une carte » :
  - réutiliser les remplacements d'événements chiffrés (`eventReplacement` : blessures, perte et gain de PV, pioche, meule, marqueurs, jetons, mana, dégagement ; R1) et les multiplicateurs de déclenchements (`triggers.ts`) ;
  - réutiliser les permissions de lancer (`grantPlay`, `castTerms`) et les modifications à l'arrivée (`StackItem.arrival`).
- Une capacité d'un permanent inflige ses blessures avec ce permanent pour source (`damageSource`).
- Les scripts de cartes vont dans `packages/cards/src/<ext>/`. Les textes des cartes manquantes s'obtiennent avec `npm run coverage -- --set <ext> --text`.
